# RustDesk 组网方案选型：ZeroTier、EasyTier、Tailscale 对比

在 [用 RustDesk 与 ZeroTier 搭自用服务器](/posts/rustdesk-zerotier) 那篇里，我用虚拟局域网把公司虚拟机、家里电脑和手机串了起来，RustDesk 直连虚拟 IP，绕开了官方中继。

用了一段时间后，延迟和不稳定的问题还是冒出来了：一旦 P2P 打洞失败，流量要绕海外中继，延迟立刻上去。于是我把目光放到另外两个方案上——EasyTier 和 Tailscale。

它们和 RustDesk 的配合方式与 ZeroTier 几乎一样，都是靠虚拟 IP 直连来降低延迟。**真正的差别在于：打洞失败之后，流量走哪里。**

## 三种方案速览

| 对比维度 | ZeroTier（当前方案） | EasyTier（国产新秀） | Tailscale（海外主流） |
| --- | --- | --- | --- |
| 核心技术 | 自研虚拟网协议，中心化 / 去中心化可选 | 基于 P2P，去中心化、无服务器，Rust 开发 | 基于 WireGuard，高效安全，云端控管 |
| 国内连接体验 | **中等**：官方根服务器在海外，打洞失败时中继延迟高 | **优秀**：全程国内服务器，专为国内网络优化 | **较差**：中继节点全在海外，打洞失败延迟飙升，易被运营商 QoS 限速 |
| 打洞成功率 | **一般**：对称型 NAT（NAT3/4）下可能偏低 | **高**：打洞积极，实测直连成功率可达 94.2% | **高**：WireGuard 打洞能力强，但受国内运营商策略影响 |
| 操作难度 | **低**：注册账号、创建网络 ID、客户端加入后需后台授权 | **极低**：无需注册，同一密钥即可组网，有中文 Web 控制台 | **极低**：一键安装登录，自动组网 |
| 免费额度 | 免费 50 台设备，无带宽限制 | 完全免费，无设备 / 带宽限制 | 个人免费 100 台设备、3 个用户 |
| 灵活性 | **极高**：支持自定义 IP 段、路由规则，可自建根服务器 | **中**：够用，配置项少 | **高**：支持子网路由、ACL、Exit Node |
| 运维成本 | 低（官方托管）；自建根节点需运维 | **零运维**：去中心化 | 零运维；自建 Headscale / DERP 需运维 |
| RustDesk 兼容性 | 极佳 | 极佳 | 极佳（官方有配合文档） |

> 表格里的成功率、延迟数字来自社区实测和反馈，不同网络环境下差异会比较大，只作参考。

## 国内网络是决定性因素

### EasyTier：面向国内网络的国产方案

EasyTier 由 Rust + Tokio 驱动，开源、去中心化，针对国内复杂的网络环境做了不少优化：

- **全程国内节点**：不依赖海外服务器，中继也在国内，从根上避免绕道带来的高延迟
- **积极的 NAT 穿透**：UDP 打洞配合 QUIC 回退，在运营商级 NAT 下仍能保持较高直连成功率
- **协议灵活**：TCP / UDP 都支持，UDP 被 QoS 限速时可以切到 TCP 保底

### Tailscale：技术先进，但国内水土不服

- **中继节点在海外**：官方 DERP 全在境外，打洞失败后流量绕香港、日本，延迟会从几十毫秒涨到 150ms 以上
- **运营商 QoS**：跨省 UDP（尤其是 WireGuard 流量）容易被限速甚至阻断
- **想用好得折腾**：通常需要自建 Headscale + 国内 DERP，技术门槛不低，也就违背了"零配置"的初衷

### ZeroTier：可控性最高，但需要调教

- 官方托管省事，但根服务器在海外
- 好处是**可以自建 Moon 节点**：在国内云服务器上部署私有中继，同样能明显改善延迟

## EasyTier 需要自己搭服务器吗

不需要。它是去中心化的，不区分客户端和服务端，任何设备都是网络里平等的节点，提供三种模式：

### 模式一：官方公共共享节点（零配置）

所有设备连到官方公共节点（如 `public.easytier.top`），由它协助设备互相发现、尝试建立 P2P 直连。

- **优点**：真正零配置，无需公网 IP，安装后填网络名称 + 密码即可组网
- **缺点**：打洞失败时走公共中继，速度和稳定性受公共节点带宽影响，高峰期可能变慢
- **适合**：作为第一步尝试，花几分钟验证自己网络下的打洞效果

### 模式二：自建中继节点（性能最优）

自备一台有公网 IP 的国内云服务器跑共享节点。

- **硬件**：2 核 4G 就够，选国内厂商延迟更低
- **部署**：有 Docker 镜像和一键脚本，在服务器上直接跑 `easytier-core` 也能启动
- **优点**：延迟最低、完全可控，流量全走自己的服务器，不受第三方影响
- **适合**：追求最佳远程桌面体验——这也是 EasyTier 在国内相对 ZeroTier 最大的优势

### 模式三：纯 P2P（无服务器）

开启 P2P-only，完全禁止流量通过任何中继转发，强制直连。

- **优点**：隐私性最好，流量不经过任何第三方
- **缺点**：复杂 NAT 环境下（公司网络、运营商级 NAT）打洞可能失败，且没有退路
- **适合**：不建议首选，等确认 P2P 稳定后再考虑

## 结论

- **首选 EasyTier**：先用模式一测打洞，够用就一直用；不够就上一台国内服务器跑模式二
- **不想换就优化 ZeroTier**：自建国内 Moon 节点，同样能缓解延迟
- **Tailscale 暂不考虑**：除非愿意投入精力自建 Headscale + 国内 DERP

EasyTier 相当于"加强版、国内特供版"的 ZeroTier，能把精力从"解决网络连通性"重新放回远程桌面本身。
